# BTC 동조 관제 · Correlation Radar

비트코인과 상관관계가 있는 자산들의 흐름을 한 화면에서 함께 보는 관제용 웹앱.
"BTC 혼자 보면 노이즈, 같이 보면 신호" — 비트코인이 자체 사이클로 움직이는지,
거시 리스크온/오프에 끌려가는지를 판별한다.

## 화면 구성

- **① 종합 판정** — 리스크온 / 중립 / 리스크오프 3단계 + 거시 동조 강도
- **② 상관 스펙트럼** — −1(역행) ↔ +1(동행) 축 위에 자산 배치. 점선 꼬리는 60일 전 위치
- **③ 동조 계기판** — 30일 상관계수를 반원 바늘 게이지로 표시
- **④ 정규화 흐름 비교** — 시작일=100 오버레이. 기간 1M/3M/6M/1Y/2Y 전환
- **⑤ 지표 현황** — 수치 + 스파크라인 (빨강 상승 / 파랑 하락)

## 추적 자산

동조(+) 후보: 나스닥100 · S&P500 · 코스피 · ETH · 금
역행(−) 후보: 달러인덱스 · 미10년물 금리 · VIX
심리·유동성: 크립토 공포탐욕 · ETH/BTC 비율 · BTC 도미넌스 · 미국 M2

상관계수는 일간 로그수익률 기준 피어슨 계수이며, 거래일이 겹치는 날짜만 사용한다.

## 배포 방법

### 1. GitHub Pages (프론트)

1. 이 저장소를 GitHub에 올린다 (`index.html`이 루트에 있어야 함)
2. Settings → Pages → Source: `main` 브랜치 / `/root` 선택 → Save
3. 몇 분 뒤 `https://<사용자명>.github.io/<저장소명>/` 에서 열림

`index.html` 하나로 동작하는 단일 파일 앱이라 별도 빌드가 필요 없다.

### 2. Cloudflare Worker (프록시) — 이미 배포됨

`worker.js`는 시세 CSV 중계용 Worker다. 이미 아래 주소로 배포되어 있고,
앱의 기본 프록시 주소로 설정되어 있다.

```
https://px-proxy.a01032767223.workers.dev
```

Worker를 새로 만들거나 재배포할 때는 Cloudflare 대시보드에서
**Workers & Pages → 해당 Worker → Edit code** 로 들어가
`worker.js` 내용을 붙여넣고 **Deploy** 한다.
(로컬 폴더에 연결된 편집기는 저장 권한 문제가 생기므로 `Edit code`를 쓸 것.)

배포 확인: `https://px-proxy.<계정>.workers.dev/health` → `ok`

프록시 주소를 바꾸려면 앱 하단 **데이터 연결 설정**에서 입력하면
브라우저 localStorage에 저장된다.

## 문제 해결

- **특정 지표만 `Load failed`** — Yahoo 심볼 문제일 수 있다. 앱 하단 설정의
  **연결 테스트** 버튼으로 어느 경로가 살아있는지 확인한다.
- **전부 실패** — Worker `/health`가 `ok`인지, 앱 설정의 프록시 주소가 맞는지 확인.
- **Yahoo가 형식 이상(HTML)을 반환** — Yahoo가 일시적으로 검증을 걸 때가 있다.
  잠시 후 다시 시도하거나, 공개 프록시 경로가 자동으로 대체한다.
